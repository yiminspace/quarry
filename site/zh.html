为什么是 Quarry

Agent 需要的保障,和人不一样

DBeaver、TablePlus、pgAdmin —— 都是好工具,但都是为"人在点击"设计的。而越来越多的查询由 AI agent 在 skill、脚本、CI 里执行。agent 不会"自己小心",工具必须替它小心。

{} 机器能解析的结果

GUI/MCP/Rust 返回 {columns, rows, rowCount, truncated, elapsedMs, engine, sql};CLI JSON 输出行数组 —— 稳定的结构化契约。不用爬屏幕,不用解析文字。

▣ 安全栏长在内核里

查询入口共享默认只读和行数限制。写入需显式授权:CLI/MCP 对 prod 额外确认,Rust 由调用方取得授权;GUI 查询保持只读。

± 确定性的错误契约

CLI 查询退出码区分成功、连接/执行失败和安全拦截;参数及其他命令的错误含义另有约定。GUI/MCP/Rust 提供结构化错误,详见下方接口契约。

我们没有往数据库 GUI 上钉一个聊天机器人。
你的 agent 本来就是 —— Quarry 给它一个通往数据的安全插座。

给人的那张脸

也是一个真正好用的工作台

qy gui 打开内置的网页工作台：分组连接与结构浏览、多标签 SQL 编辑器、补全与 EXPLAIN、历史搜索、类型着色网格、JSON 查看、Redis 命名空间树，以及 CSV/JSON 导出。支持亮暗主题、中英双语。独立模式通过浏览器存储保留草稿和有大小限制的结果快照；大结果仅留在当前会话。

✦ 编辑器旁的 SQL 助手

结合表结构解释、生成和修改 SQL。建议可写入编辑器，也能恢复修改前的 SQL；查询仍需手动执行。

▣ 草稿与执行由你掌控

打开表时保留已写的 SQL。明确标记为生产的连接默认关闭自动执行，需要你为相应目标主动开启。

⇄ 结果跟随当前标签

网格与导出使用当前标签的结果。请求重叠时保留最新结果，旧响应不会覆盖它；排序、分页、查看和取消都保留目标归属。

架构

一核多脸

连接管理、查询执行、schema 内省、安全栏都在一个可 import 的内核里,其余全是薄壳。共享修复惠及各查询入口;授权方式和错误呈现由各入口明确约定。

托管工作台 · 一个 Docker 镜像

你的 IAM、你的数据库，同一个工作台

官方 Docker 镜像加一个配置文件，就能提供网页、登录、只读 API 和查询执行。可用内置管理员，也可配置接入已有 IAM。YiminLab 使用同一个镜像；原有 Quarry 本地模式保持独立。

▣ 平台控制只读访问

只展示平台登记的资源。每次远程查询、结构查看、取消和 schema 导出都检查实时 IAM 权限与资源授权，数据库连接凭据保留在服务器。

⌁ 个人工作保存在自己电脑

运行 ylab db connect 后自动打开工作台，将草稿、标签、查询历史、有限结果缓存、助手对话和生成 SQL 保存到电脑上的 SQLite，网页与 CLI 共用账号隔离的记录。断开时由有限的浏览器恢复副本保护待保存内容。

⇄ 断开连接也能继续编辑

首次成功加载后，可用缓存的页面离线重新打开工作台。远程和本机分别显示连接状态；重连不会自动执行 SQL、启动 Docker、导入结构或替换未保存草稿。有效配对授权内，本机操作可继续离线使用。

▤ 配置一次，打开就查

镜像自带工作台和查询服务。数据库连接、访问账号和登录方式通过配置提供，不需要编写 Rust IAM 适配器或定制构建网页。本机连接和个人记录保存都在后台完成，仅在需要处理保存冲突时提供恢复选择。

远程查询会把 SQL 发送到平台；助手会把所需上下文发送到配置的模型网关，日志保留遵循平台策略。托管共享 SQL、云端个人历史与跨设备同步暂未实现。

查看托管部署指南 一个镜像、一个配置文件；支持独立登录或已有平台账号。
安全栏

默认只读。放行是显式且分级的。

CLI 写入需 --write，生产目标还需确认或 --yes；MCP 需服务端和调用同时授权，生产额外要求 confirm_prod。Rust 调用方提供显式写入授权；GUI 与托管查询只读。无外层 LIMIT 的读查询默认 500 行，--max-rows 0 可取消；工具/锁定查询不改写，Redis 在取回后截断。生产保护取决于连接的明确标记，与环境名称无关。

Workspace 即代码

你的连接和查询是文件,不是点点点

独立模式的 workspace 是一个目录：connections.toml 加上带元信息头的 .sql 命名查询。查询文件和不含凭据的配置模板可放进你的仓库；真实连接凭据留在本机。多个 workspace 可聚合到同一视图。这些本地查询文件与托管个人历史分别管理，托管共享查询库尚未实现。

connections.toml
[shop_dev]
url    = "postgresql://user:password@dev.example.com:5432/shop"
db     = "shop"
env    = "dev"

[shop_prod]
url    = "postgresql://user:password@prod.example.com:5432/shop"
db     = "shop"
env    = "prod"
production = true

[internal_db]
url      = "postgresql://user:password@127.0.0.1:5432/appdb"
ssh_host = "bastion.example.com"  # auto tunnel
queries/shop/recent_orders.sql
-- @name: recent_orders
-- @db: shop
-- @desc: Latest orders with customer names
-- @param: days (int, default=7)
SELECT o.id, c.name, o.amount, o.status
FROM orders o JOIN customers c ON c.id = o.customer_id
WHERE o.created_at > now() - make_interval(days => :days)
ORDER BY o.created_at DESC;

同一个逻辑库的 dev / staging / prod 折叠成一个 env-set —— 一份命名查询跑任意环境:qy run recent_orders --env prod。

引擎与体积

近乎零依赖

Rust 单二进制，GUI 与数据库驱动内置。提供 macOS/Linux 的 arm64 与 x86_64 安装包。用安装脚本安装后，可运行 qy update 升级。SSH、Docker 和 schema sync 按需使用系统工具。

PostgreSQL · 原生 SQLx MySQL · 原生 SQLx Redis · native redis-rs Neptune · 实验性 openCypher SSH 隧道 · 系统 ssh SQLite · 内置 DuckDB · 规划中

Neptune 属于实验性支持:已提供 openCypher 端点接入,真实 AWS/IAM 行为尚未完成发布验收。本地空端点不执行或存储图数据。已验证环境、持久化限制和错误码详见支持与接口契约。

⌁ 真类库,可 import

quarry-service::QuarryService 嵌入执行内核，quarry-cli::run_from 嵌入 CLI，quarry-platform 提供托管授权与配对本机服务。不依赖另装的 qy 或 Python 子进程。

▣ 自己选择运行位置

独立 Quarry 连接你配置的数据库，GUI 默认绑定 localhost。托管模式运行在你自己的平台，Quarry 没有中心云账号。模型请求发往你配置的服务。GitHub Release 更新检查可用 QUARRY_UPDATE_CHECK=0 关闭。
